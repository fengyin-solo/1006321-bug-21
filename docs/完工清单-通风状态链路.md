# 通风机组状态链路 · 完工清单

> 本文件是本次需求的验收完工清单。页面里的「验收完工清单」（`CompletionLedger.vue`，
> 概览页与渗漏水处置页共用同一份数据）与本文件描述的是同一条规则：验收结果只有一个落点，
> 其他入口只读不另存，概览条数与另存清单条数一致。

## 1. 上报故障后列表/详情/页脚台数不一致 —— 已修复

**根因**：旧实现里状态是扁平行上的一个可平推字段（`runAction` 直接覆盖 `status`），而通风页
页脚三张统计卡在页面里写死为 `0`（旧 `ventilation/index.vue` 的 `stats` 常量），图例又是
`rows` 的临时过滤结果 —— 列表、详情、页脚三处没有共同数据源。

**修复后的链路**：

- 机组当前状态不再允许平推，只能由**生命周期事件链**末尾推导
  （`src/domain/fan-lifecycle.ts` 的 `deriveFanState`）。
- 列表行是事件链的**投影**（`src/data/local-store.ts` 的 `fanProjectionRow`），
  详情面板、页脚统计卡、状态图例、交接班核对台数、概览异常量全部调用
  `fanCounters()` / `deriveFanState()` 取同一份推导值。
- 上报故障后：事件链追加 `运行中 → 故障停机`，事务一次落库
  （`commitDatabase`），投影行随之刷新，页脚运行中减一、故障停机加一。

## 2. 生命周期单向链路（含改档恢复顺序）

```
待开机 ──提交开机(必填运行模式)──▶ 运行中
运行中 ──登记停机(必填停机原因)──▶ 已停机
运行中 ──上报故障(必填故障原因)──▶ 故障停机
已停机 ──提交开机(可换新档位)──▶ 运行中
故障停机 ──故障恢复──▶ 已停机 ──提交开机──▶ 运行中
```

- 跳着切换一律打回，返回信息写清**卡在哪一段、下一步该走哪条边**，例如
  故障停机直接开机：`当前卡在「故障停机」段，只能先「故障恢复」，不能直接「提交开机」`
  （`validateTransition` 返回 `blockedSegment` / `expectedAction`）。
- 中途改档也照原顺序恢复：运行中点「申请改档」直接打回，必须先登记停机，
  重新提交开机时才允许选新档位（有单测覆盖）。
- 每次提交把**状态 + 运行模式 + 停机原因 + 操作人 + 时间**写进同一条事件，一次落库；
  重新开机时上一轮停机原因清空，故障恢复回已停机时原因保留可查。

## 3. 同一机组重复上报只置一次故障

一轮运行中 `faultActive` 只置一次：故障停机态再次上报直接幂等打回
（`buildEvent` 先判 `faultActive`），不追加第二条故障事件。
故障恢复 → 重新开机后进入新一轮，才允许再次上报。单测覆盖两轮场景。

## 4. 存量机组回填裁决（可裁决项，理由在此）

裁决：**只信启停时间与运行模式，按它们补事件；早年没有故障记录的，绝不补故障停机。**

- `运行中`：有启停时间就补一条 `提交开机` 事件，模式沿用原值。
- `已停机`：补正常停机事件；停机原因当时没登记的，留 `null`，不编默认原因。
- 旧版平推成 `故障停机` 但查无故障记录：**新旧两版冲突，以新版事件链为准**，
  降级为 `已停机`；旧值原样保存在 `legacyStatus`，仅作留痕，不参与统计。
  理由：故障停机意味着真实的设备损害与检修责任，没有故障记录佐证就不能凭一个可随意平推的
  状态字段判定；宁可降级为保守的「已停机」，也不虚构故障。
- 启停时间无法解析：事件时间留 `null`，不编造时分秒。
- 纯待开机、无模式无时间：保持待开机，不补任何事件。

## 5. 新旧两版取值：以新版为准，旧版只作留痕（可裁决项，理由在此）

- **判定以新版（v2 事件链）为准**。v1 只有扁平行 `status`，无法表达「故障 → 恢复 →
  再开机」的顺序，也没有停机原因，它只能描述一个瞬时截面、不能描述生命周期；
  v2 的事件链天然可追溯、可重放，当前态由事件推导，不可能出现「详情一个态、列表一个态」。
- v1 原始数据不删除：保留在原 localStorage 键 `urban-utility-tunnel:entries`；
  迁移产物写入新键 `urban-utility-tunnel:db:v2`，机组上的 `legacyStatus` 字段
  与回填事件备注里都能看到旧值。两版取值保留新版，理由同上：事件链的信息密度与一致性
  保证都强于可平推字段。

## 6. 老处置记录补录

- 渗漏水处置存量记录迁移为 `disposalTraces`，**按发现日期倒排**
  （空发现日期排最后），页面见「渗漏水处置」页的补录表。
- 缺值一律 `null`，页面显示「未登记」，不拿默认值顶上。

## 7. 验收完工清单（其他入口读到同一份）

- 唯一落点：`db.completions`。渗漏（确认完工）、检修（确认完工）、隐患（提交验收）
  等来源入口验收时由通用 `runAction` 统一写入；重复验收幂等，不新增。
- 其他入口（运营概览页、渗漏页）通过 `CompletionLedger.vue` 只读同一份；
  「另存清单」导出的 CSV 也由同一列表生成。
- 概览卡片「验收完工数」= `completions.length` = 清单行数，有一致性校验
  （`checkCountConsistency`，单测覆盖）。

## 8. 同步断线续传（不拿上一次的值顶）

- 每个机组动作入 outbox 时冻结载荷快照（状态/模式/停机原因），
  同步只发该快照，绝不回读机组当前值。
- 同步只从**第一条未同步成功**的记录开始；该条失败立即中断，后面记录保持未发；
  恢复后仍从失败那条重试（带 attempts）。断线时一条都不发。
- 通风页底部「上行同步队列」面板可切链路在线/断线、触发同步、查看卡点。

## 10. 验收方式

```bash
cd frontend
# 领域规则单测（23 项）：
node_modules/.bin/esbuild tests/lifecycle.test.ts --bundle --platform=node \
  --format=cjs --alias:@=./src --outfile=node_modules/.tmp/test.cjs \
  && node node_modules/.tmp/test.cjs
# 类型检查与构建：
npm run typecheck && npm run build
```

手工验收路径：通风页对「运行中」机组点上报故障（填原因）→ 详情与列表同时变故障停机、
页脚台数变化；对故障停机机组点提交开机会被打回，必须先故障恢复；交接班级台数核对与
通风页一致；同步面板切断线后动作入队不发送，恢复后从首条未成功记录续传。
